# Clash 链式代理配置技能

当搬瓦工（BandwagonHost）等 VPS 的 IP 在国内被封、国内直连超时，但机场节点仍能访问该 VPS 时，可以在 Clash Verge Rev / Mihomo 中增加可选的前置机场，继续使用原有 VPS 出口或 VPS → 住宅 IP 出口。

这个项目提供一个可复用的 Codex skill，带用户收集已有配置、生成完整扩展脚本和扩展覆写、手动应用并验证实际连接。默认在原有 VPS 远程订阅上修改，保留订阅卡片的刷新功能。

## 适用条件

- 已有一个可以正常使用的机场订阅。
- VPS 代理服务正常，并且至少有一个机场节点能连接 VPS 的入口地址与端口。
- 已有“纯 VPS”和“VPS → 住宅 IP”两个客户端入口节点。
- VPS → 住宅 IP 的服务器侧路由已经配置好，例如已在 3X-UI 中配置对应入站和出站。
- 使用支持相关协议与 `dialer-proxy` 的 Mihomo 内核。按实际客户端版本检查兼容性。

前置机场改变的是电脑访问 VPS 的路径。VPS 的国内直连可达性需要单独测试。VPS 宕机、入口服务停止、机场也无法连接 VPS 或住宅代理失效时，需要继续排查对应环节。

## 可以选择的路径

| 前置机场选择 | 出口选择 | 实际路径 |
| --- | --- | --- |
| 一个机场节点 | 纯 VPS | 电脑 → 机场 → VPS → 网站 |
| 一个机场节点 | 住宅出口 | 电脑 → 机场 → VPS → 住宅 IP → 网站 |
| 不经过机场（直连） | 纯 VPS | 电脑 → VPS → 网站 |
| 不经过机场（直连） | 住宅出口 | 电脑 → VPS → 住宅 IP → 网站 |

机场节点通过 provider 动态加载。用户可以切换前置节点，也可以选择直连前置，测试 VPS 的国内直连是否已经恢复。

## 安装与调用

在有 GitHub 访问能力的 Codex 中发送下面的请求。

```text
请使用 skill-installer 安装这个仓库里的技能：
https://github.com/Draymond-Sreike/clash-chain-routing
技能路径为 skills/clash-chain-routing。
```

安装后在下一轮消息中调用。

```text
使用 $clash-chain-routing。

我的 VPS 国内直连受阻，已有纯 VPS 和 VPS→住宅两个节点，
服务器侧路由已经配好，需要增加可选的前置机场。

请先逐步告诉我到 Clash 的哪些位置截图、复制资料，收齐后
在原 VPS 远程订阅上配置，保留刷新入口。
使用技能中的国内直连和 DNS 分流基线，核对本机进程名及特殊规则。
交付完整的订阅扩展脚本和订阅扩展覆写，并带我验证真实出口。
```

也可以下载完整仓库，在 Codex 中明确提供解压后的 `skills/clash-chain-routing/SKILL.md` 绝对路径，请它读取并使用。保留技能目录内的 references、assets、scripts 和 agents。

## 需要从 Clash 收集什么

以下菜单已在 Clash Verge Rev v2.5.9 中文界面核对。其他版本菜单有差异时，先提供对应页面截图。

| 资料 | 获取位置 |
| --- | --- |
| 客户端和内核版本 | 设置 → Verge 版本、Clash 内核，分别截图 |
| 目标订阅 | 订阅页面截图，指出可用机场卡片和准备修改的 VPS 卡片 |
| 机场链接、用户代理 | 机场卡片右键 → 编辑信息 → 订阅链接、用户代理 |
| 机场原配置 | 同一张机场卡片右键 → 编辑文件，复制全部正文 |
| VPS 链接和原配置 | VPS 卡片右键 → 编辑信息、编辑文件 |
| 两个入口用途 | 写明纯 VPS 节点名和住宅出口节点名 |
| 原订阅扩展 | VPS 卡片右键 → 扩展覆写配置、扩展脚本，分别复制全文 |
| 全局扩展 | 订阅页底部 → 全局扩展覆写配置、全局扩展脚本 |

复制代码时先点击编辑器正文，再按 Ctrl+A、Ctrl+C，粘贴到记事本保存为 `.txt`。资料收集完成后点击取消。用过“编辑规则”“编辑节点”“编辑代理组”的用户还需说明对应修改。

订阅链接、节点配置和专用 DNS 链接可能包含凭据，通过私密渠道提供给配置助手。公开 issue 使用脱敏日志与合成示例。

## 最终交付与粘贴位置

| 交付文件 | 功能 | 粘贴位置 |
| --- | --- | --- |
| 订阅扩展脚本.txt | 前置机场、两个出口、机场专用 DNS 适配 | 原 VPS 卡片右键 → 扩展脚本 |
| 订阅扩展覆写.txt | 国内直连、进程规则、规则集、DNS 和默认出口 | 同一张卡片右键 → 扩展覆写配置 |

先备份两处原内容，按交付说明完整替换对应文本。保存可能触发重载和短暂重连，可在使用其他可用订阅时编辑目标卡片。两份保存后再使用目标订阅，进入“代理”选择前置机场和出口。配置助手应核对扩展执行顺序及最终合成结果。

详细操作见 [资料收集与导入](skills/clash-chain-routing/references/intake-and-import.md)。

## 默认分流行为

- 微信、企业微信、QQ 音乐、抖音、ToDesk、UU 远程等指定 Windows 进程直连，具体进程名按目标电脑核对。
- 知网、分区表等明确指定的网站直连。
- 本机和内网地址直连。
- 域名命中国内名单且目标 IP 属于中国时直连。
- 前面尚未匹配的国内 UDP 流量直连，这会覆盖其他应用的部分国内 UDP 连接。
- 国内名单使用国内 DNS，其余域名使用加密 DNS，DNS 连接遵循分流规则。
- 其余流量使用当前选择的 VPS 或住宅出口。

公开分流基线移除了个人 SSH 地址、个人面板和物联网地址。需要这些规则时按目标环境添加。应用进程无法识别时，连接继续匹配后续规则。正式验收应查看连接规则和实际公网出口。

## 更新与维护

VPS 订阅卡片刷新与机场 provider 更新各自独立。机场节点可按 provider 周期更新，更新失败时可能继续使用缓存。机场订阅令牌更换、特殊 DNS 改动、客户端标识影响订阅返回内容或机场采用新协议时，需要重新核对。

当前脚本模板通过节点名、服务器和端口确认两个 VPS 入口。更新后这些字段发生变化会报错，需要重新确认对应关系。其他连接字段从原订阅节点保留。

遇到“单独机场能用，链路前置全部超时”，优先对比实际订阅 URL、用户代理、节点协议、更新时间和机场专用 DNS，再逐段检查 VPS 与住宅出口。

## 验证范围

发布前已完成技能格式校验、25 项合成数据脚本检查，以及通用分流覆写与生成脚本的组合检查。端到端可达性、速度、UDP 支持和真实出口取决于实际机场、VPS、住宅代理与本机环境，需在目标电脑完成验收。

技能提供临时隔离验证的流程，测试实例关闭 TUN、使用独立目录和回环端口，结束后清理该实例。正式配置还需单独核对。默认工作流通过已有节点资料配置客户端链路，服务器路由调整由用户另行明确范围。
