# Clash 可选前置与双出口

使用中文带用户完成资料收集、配置生成、导入和实际验证。用户通常已有两个连接到 VPS 的客户端节点，住宅代理及 3X-UI 路由已在服务器侧配置。

默认在现有 VPS 远程订阅上添加订阅级扩展脚本，保留订阅卡片的刷新入口。交付完整可复制脚本，读取每次订阅更新后的节点参数并添加链路设置。用户明确选择本地文件时才采用独立 YAML。收集原订阅链接、原配置、订阅级覆写和脚本、全局扩展，核对既有处理功能与执行顺序。

默认配套交付完整“订阅扩展覆写.txt”，采用 [通用分流基线](assets/routing-override.yaml) 并按目标电脑适配。该基线由用户指定的现有分流整理，说明见 [分流迁移](references/configuration-and-validation.md#分流迁移)。用户明确要求沿用另一套规则时按其要求处理。交付两份文本各自粘贴的位置和配置组合后的验证结果。

目标界面有两个选择组。

| 选择组 | 作用 |
| --- | --- |
| 前置机场 | 机场订阅中的全部兼容代理节点，以及“不经过机场（直连）” |
| 出口选择，或原有 AI服务 / PROXY | 纯 VPS 出口、VPS → 住宅 IP 出口 |

两个 VPS 入口节点的 `dialer-proxy` 指向前置组。机场 provider 节点通过 `DIRECT` 连接其服务器。选择前置组的“不经过机场（直连）”只跳过机场，最终出口仍由出口组决定。

## 1. 先收齐资料

先读 [资料收集与引导](references/intake-and-import.md)。利用用户已提供的上下文，先读取允许访问的本机配置，向用户说明已知项，再询问缺失项。遵守用户对一次一个问题或一次收齐的偏好。必需信息未齐时，先完成可独立进行的核查，待资料齐全再生成可应用配置。

必须确认目标设备与客户端/内核版本、新建或修改订阅、两个入口节点的角色、目标机场订阅、现有分流处理方式、用户手动导入或已授权代操作。远程电脑无法读取时，接收用户导出的配置、订阅或节点分享链接。截图用于确认名称和角色，连接所需参数从实际配置获得。

本机已有“纯 VPS”和“住宅出口”时，从对应订阅读取节点。节点名相同也要按实际服务器、端口及协议确认身份。服务器侧已接好住宅出口时，客户端阶段使用两个 VPS 入口节点即可。

## 2. 核对真实订阅与协议

在开发配置前读 [配置与验证要点](references/configuration-and-validation.md)。采集当前配置及独立机场的可用基线，记录目标订阅 UID/名称、已选前置、出口和客户端状态。

核对独立机场订阅与链路 provider 的实际 URL、获取日期、节点数、协议类型、同名节点的服务器/端口及认证参数是否一致。只报告相同/不同和字段名。订阅链接、密码、UUID、DNS URL 内的用户令牌存入用户专属产物，禁止带入此公共技能包或排障输出。

用真实内核支持的客户端标识获取订阅。对新取回内容进行协议/节点数检查，和独立机场当前缓存比较并解释差异。曾验证旧标识 `ClashMeta/1.19.0` 会让某机场仅返回 HY2，而当时对应内核标识会返回 AnyTLS、Mieru 等协议。将它作为应验证的兼容性问题，客户端版本每次读取。

从同一份机场订阅提取实际节点需要的专用域名解析策略，补充到 Mihomo 节点解析策略。保留认证 URL 内的内容，按已核实的解析路径设置路由。机场通常只返回代理节点供 `proxy-provider` 加载，原订阅 DNS 需要单独处理。特殊 DNS 随订阅账号或机场更换时重新核对。

## 3. 生成可检查的候选产物

在工作目录建立用户专属输出目录，并记录原配置/原订阅脚本的备份。修改原订阅时先理解、组合已有脚本功能，避免直接覆盖有其他用途的原脚本。

对于普通的两个出口、一个前置选择组，使用 [脚本模板](assets/subscription-script.js) 和 `scripts/build_script.cjs` 生成完整 Clash Verge 订阅脚本。参数契约见配置参考文档。复杂原配置触发模板保护时，先解释具体冲突并针对实际配置调整候选，保留原规则语义。

新建本地订阅时，将已验证的两个真实入口节点、前置 provider、两个选择组、用户确定的 DNS 和分流组成一份完整可导入 YAML。可先用模板生成结果再序列化交付，让用户通过“订阅 → 新建 → 类型选本地 → 选择文件”导入。说明机场 provider 会定期更新，而写入 YAML 的 VPS 参数改变后需要重新生成。若用户要求 VPS 节点也自动更新，采用现有远程 VPS 订阅加订阅级脚本的方式，并单独说明粘贴位置。

远程订阅卡片刷新更新 VPS 来源，机场 provider 按自身周期或单独操作更新。分别验证两者，避免承诺一个刷新按钮同步更新所有来源。当前模板按名称、服务器和端口核对入口身份，任一变化会报错并需重新确认映射。报告此边界，避免承诺所有 VPS 变更均可无干预适配。若 VPS 订阅地址自身已不可达，先确认可用机场更新路径与缓存，防止更新依赖尚未建立的同一链路。

交付清楚区分完整 YAML、完整订阅脚本和全局脚本的位置。提供一份可直接完整复制的 `.txt` 脚本，避免让技术新手拼接片段。前置组使用 `proxy-providers` 自动获取机场节点，过滤内容限于已确认的套餐/流量/官网占位项。

## 4. 分层验证后引导应用

先验证生成脚本、幂等性和配置结构，比较两个入口的连接参数、rules、rule-providers、普通 DNS。迁移分流时，以用户选定的分流基线核对规则和 DNS，并列出相对朋友原配置的预期差异。核对覆写、脚本与全局扩展处理后的最终配置，确认两组选择、机场解析策略及规则均保留。用目标机器实际 Mihomo 做配置检查，受环境限制时明确记录未完成项。

进行联网隔离验证时使用候选中的真实 provider 来源和请求标识。临时实例关闭 TUN，使用独立目录和随机回环端口。将启动、检查、停止放进同一带 `finally` 的前台任务，只清理本次实例，并确认其进程及监听已消失。

按参考文档检查前置本身、机场 → 纯 VPS、机场 → VPS → 住宅出口，以及跳过机场后的两个出口。记录测速网址、超时上限、当前选项和实际公网出口。报告隔离测试与正式配置验证各自的完成状态。

依据用户授权和文件边界应用。手动模式按交付类型逐步引导。完整 YAML 用“新建 → 本地 → 选择文件”导入。完整订阅脚本用目标订阅右键菜单的“扩展脚本”完整替换保存，再使用目标订阅、选择前置及出口。菜单文字每次按目标版本核对。每次停在用户能确认的具体界面或结果。代操作模式也应先使候选与差异可检查。

正式导入后，读取运行时 provider 数量、两个选择组、实际连接及出口再确认完成。尚需用户保存/导入时，明确剩余动作。

## 5. 日常切换与恢复测试

教用户以下三种操作，并写明实际组名和节点名。

1. 更换机场线路，在前置组选择另一节点。
2. 测试国内直连 VPS，出口组选“纯 VPS”，前置组选“不经过机场（直连）”，测试真实请求和公网出口。单次通过仅说明测试时可达。
3. 使用住宅出口，出口组选住宅入口。前置组选机场节点时为完整链路，前置选直连时为电脑 → VPS → 住宅。

主动直连恢复测试可能改变正在使用的出口。优先隔离实例，或先让用户了解测试期间的出口并确认时机。记录原选项，测试失败或用户仅要求探测时恢复原选择。

## 排障边界

测速超时先保存现场，对照同一节点参数、同一 DNS、同一测速目标和同一超时限制。测速请求可能包含目标域名解析开销，选择组测速只代表其当前选中的节点。

TUN/热点问题和机场链路问题分别取证。开关 TUN 或内核重启若超时、旧进程残留、配置与网卡状态不一致，停止重复切换，先读取核心、服务和监听状态，报告恢复方案。

本技能的客户端链路工作以读取已有服务器连接资料为基础。用户另行要求服务器路由调整、系统服务修复或热点共享变更时，明确新增范围及其授权。

最终用简短中文交付文件入口、粘贴位置、推荐起始选择、实际测试结果、直连恢复测试方法和回退方式。技能包本身保持去凭据、去用户专用 IP/路径，账号配置归入用户专属工作产物。
